# Codex 작업 규칙

이 문서는 앞으로 이 프로젝트에서 Codex가 따라야 할 기본 규칙이다.

## 기본 원칙

- 기존 프로젝트 파일은 사용자 허락 없이 수정하지 않는다.
- 기본 작업은 `codex/` 폴더 안에 기록을 남기는 것이다.
- 코드 수정이 필요하면 먼저 계획만 제안하고 허락을 받은 뒤 진행한다.
- 사용자의 명시적 요청이 없으면 실행, 설치, 재생성, 리팩터링을 하지 않는다.
- 기존 프로젝트 구조나 목적이 불명확하면 추측과 확인된 사실을 구분해서 기록한다.
- 현재 제품 방향은 실제 지도 서비스보다 기부 캠페인 검색 서비스에 가깝다는 사용자 답변을 기준으로 판단한다.
- 이 프로젝트의 핵심은 특정 LLM 모델 사용이 아니라 크롤링한 데이터를 적절히 정제하는 것이다.

## 작업 전 규칙

- 작업 전 `git status`를 확인한다.
- `.git`이 없으면 Git 저장소가 아니라고 기록만 남기고 `git init`을 실행하지 않는다.
- 요청 범위를 먼저 확인하고, 허용된 파일과 금지된 파일을 구분한다.
- 기록 전용 작업에서는 기존 프로젝트 파일을 읽기만 한다.

## 작업 중 규칙

- `README.md`, `package.json`, `package-lock.json`, `server.js`, HTML 파일, JSON 데이터 파일, `src/`, `scripts/`, `processed/`는 사용자 허락 없이 수정하지 않는다.
- 생성 결과물이나 데이터 파일은 원인 확인 없이 직접 수정하지 않는다.
- 한글 인코딩 문제가 보여도 자동 복구하지 말고 먼저 기록만 한다.
- 한글 깨짐 문제는 원인 분석 후 복구 계획을 먼저 작성하고, 실제 복구는 사용자 허락 후 진행한다.
- 프로젝트 결과값이 갱신될 때마다 `codex/work-log.md`에 기록한다.
- 실행, 설치, 데이터 재생성 명령은 사용자 허락 없이 실행하지 않는다.
- 특히 `npm install`, `npm run`, `node`, `git init`, `git add`, `git commit`, 자동 포맷팅, 인코딩 변환, 파일 정리 명령은 명시적 허락 전에는 실행하지 않는다.
- `processed/campaigns.json`과 `processed/cache.json`은 결과 데이터로 보고 직접 편집하지 않는다.

## 작업 후 규칙

- 작업 후 변경 파일 목록을 확인한다.
- `codex/` 폴더 밖의 파일이 변경되지 않았는지 확인한다.
- 기록 문서에는 읽은 파일, 생성/수정한 파일, 수정하지 않은 주요 파일, 확인한 문제, 다음 작업 제안을 남긴다.
- 사용자에게 확인할 질문은 앞으로 프로젝트 방향을 정하는 데 필요한 질문만 최대 5개까지 정리한다.

## 허락 없이 가능한 작업

- 기존 프로젝트 파일 읽기
- `git status` 확인
- `codex/` 폴더 생성
- `codex/` 폴더 안의 기록용 Markdown 파일 생성 또는 수정

## 허락이 필요한 작업

- 기존 코드 수정
- README 수정
- package 관련 파일 수정
- JSON 데이터 파일 수정
- HTML 파일 수정
- `src/`, `scripts/`, `processed/` 내부 파일 수정
- 프로젝트 실행
- 의존성 설치
- 데이터 재수집 또는 재생성
- 테스트 실행
- Git stage, commit, push
- 자동 포맷팅 또는 인코딩 복구
