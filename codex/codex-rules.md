# Codex 작업 규칙

## 기본 원칙

- 기존 프로젝트 파일은 사용자 허락 없이 수정하지 않는다.
- 기본 작업은 `codex/` 폴더 안에 기록을 남기는 것이다.
- 코드 수정이 필요하면 먼저 계획만 제안하고 허락을 받은 뒤 진행한다.
- 작업 전 `git status`를 확인한다.
- 작업 후 변경 파일 목록을 확인한다.
- `processed/campaigns.json` 같은 생성 결과물은 직접 수정하지 않는다.
- 한글 인코딩 문제가 보여도 자동 복구하지 말고 먼저 기록만 한다.
- 프로젝트 결과값이 갱신될 때마다 `codex/work-log.md`에 기록한다.

## 현재 프로젝트 방향

- 이 프로젝트는 지도 기반 서비스보다 기부 캠페인 통합 탐색기에 가깝다.
- 다음 우선순위는 UI 개선이다.
- 한글 인코딩 문제는 복구 대상이지만, 자동 복구 전에 범위와 방법을 먼저 기록한다.
- Ollama 로컬 모델은 임시 모델이므로 특정 LLM에 강하게 종속되지 않는 방향을 선호한다.
- 수집 대상 플랫폼은 앞으로 확장될 수 있으므로 확장성을 고려한다.

## 허용되는 기본 작업

- 기존 프로젝트 파일 읽기
- Git 상태 확인
- `codex/` 폴더 안에 분석 기록, 작업 로그, 계획 문서 작성
- 사용자 요청이 명확할 때 `codex/` 폴더 안의 문서 수정

## 금지되는 기본 작업

- 사용자 허락 없는 기존 코드 수정
- 사용자 허락 없는 README 수정
- 사용자 허락 없는 `package.json`, `package-lock.json` 수정
- 사용자 허락 없는 `processed/` 폴더 파일 수정
- 사용자 허락 없는 `index.html`, `main_service.html` 수정
- 사용자 허락 없는 `src/`, `scripts/`, `bin/`, `test/` 내부 파일 수정
- 사용자 허락 없는 `npm install`, `npm run`, `node` 실행
- 사용자 허락 없는 `git init`, `git add`, `git commit` 실행
- 사용자 허락 없는 자동 포맷팅, 인코딩 변환, 파일 정리

## 코드 수정이 필요한 경우의 절차

1. 먼저 `git status`를 확인한다.
2. 기존 파일을 읽고 문제와 영향 범위를 기록한다.
3. `codex/` 폴더 안에 수정 계획을 작성하거나 사용자에게 계획을 설명한다.
4. 사용자에게 명시적 허락을 받은 뒤에만 기존 프로젝트 파일을 수정한다.
5. 수정 후 변경 파일 목록을 확인한다.
6. 실행이나 데이터 재생성이 필요하면 별도 허락을 받는다.
7. 작업 결과와 변경 사항을 `codex/work-log.md`에 기록한다.

## 데이터와 생성물 관련 규칙

- `processed/campaigns.json`은 웹 UI가 사용하는 최종 생성 결과물이므로 직접 손으로 고치지 않는다.
- `processed/cache.json`은 LLM 후처리 캐시이므로 직접 손으로 고치지 않는다.
- 데이터 품질 문제가 있으면 원인과 재생성 절차를 먼저 기록한다.
- 재수집, 재가공, LLM 실행은 프로젝트 상태를 바꿀 수 있으므로 사용자 허락 후 진행한다.

## 한글 인코딩 관련 규칙

- 한글 깨짐이 보여도 자동으로 복구하지 않는다.
- 인코딩 변환 도구를 실행하기 전에 깨진 파일 목록과 예상 원인을 기록한다.
- 복구가 필요하면 백업, 검증 방법, 영향 범위를 먼저 제안한다.
- 사용자 허락 없이 README, HTML, JavaScript, JSON 파일의 인코딩을 변환하지 않는다.

## UI 개선 관련 규칙

- UI 개선은 현재 프로젝트의 다음 우선순위다.
- UI 개선 전에는 어떤 화면, 어떤 사용자 흐름, 어떤 데이터 상태를 개선할지 먼저 기록한다.
- UI 문구나 HTML을 수정해야 할 경우 먼저 계획을 제안하고 허락을 받는다.
- 인코딩 복구와 UI 개선은 영향 범위가 겹치므로 한 번에 자동 처리하지 않는다.

## Git 관련 규칙

- 작업 전후 `git status --short --branch`를 확인한다.
- 사용자 허락 없이 `git add`, `git commit`, `git reset`, `git checkout`, `git init`을 실행하지 않는다.
- 원격 저장소 연결, 브랜치 생성, 푸시는 사용자 요청과 허락이 있을 때만 진행한다.

추가 질문 없음
