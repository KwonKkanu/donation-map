# 카테고리 및 태그 분류 개선 작업 요약

작성일: 2026-05-19

## 1. 핵심 문제

이번 작업의 핵심은 크롤링한 기부 캠페인 데이터를 검색/필터에 쓸 수 있도록 **카테고리와 태그를 안정적으로 정리하는 것**이었다.

기존 문제:

- `category` 하나에 너무 많은 의미가 섞여 있었다.
- LLM이 category를 자유롭게 만들어 UI 필터로 쓰기 어려웠다.
- 어떤 캠페인은 title이 원본과 다르게 바뀌었다.
- `tags`는 있었지만 검색/분류 진입점으로 제대로 활용되지 않았다.
- Ollama 미연결 상태에서는 모든 `target/supportType`이 `기타`, tags는 빈 배열이 되었다.

## 2. 목표 분류 구조

기존 단일 category 구조를 다음처럼 나누는 방향으로 정리했다.

```text
target = 누구를 돕는가
supportType = 무엇을 지원하는가
tags = 세부 검색/분류용 키워드
```

예시:

```json
{
  "target": "노인",
  "supportType": "식사지원",
  "category": "노인",
  "tags": ["식사지원", "시각장애인", "어르신", "독거", "장애인"]
}
```

`category`는 기존 UI/API 호환을 위해 제거하지 않고 `target`과 같은 값으로 유지했다.

## 3. 허용 목록

### target

- 아동/청소년
- 노인
- 장애인
- 여성/가족
- 저소득/취약계층
- 재난/위기
- 동물
- 환경
- 지역사회
- 해외/국제
- 기타

### supportType

- 생계지원
- 의료지원
- 주거지원
- 교육지원
- 식사지원
- 심리/정서지원
- 보호/돌봄
- 문화/여가
- 환경개선
- 긴급구호
- 인식개선/캠페인
- 기타

## 4. 처리 정책

적용한 정책:

- `titleRaw`가 있으면 최종 `title`은 항상 원본 제목을 사용한다.
- LLM이 출력한 `target/supportType`이 허용 목록 밖이면 `기타`로 보정한다.
- 최종 `category`는 항상 `target`과 같게 한다.
- tags는 최대 5개로 제한한다.
- tags는 공백/중복/너무 일반적인 단어를 정리한다.
- LLM 결과는 최종값이 아니라 후보로 보고, 코드에서 검증한다.
- 제목/요약/raw 카테고리에 명확한 키워드가 있으면 규칙 기반 보정값을 우선 적용한다.

## 5. 발생했던 주요 문제와 해결

### 문제 1. 모든 항목이 기타가 됨

원인:

- Ollama가 연결되지 않아 LLM 정제가 수행되지 않았다.
- fallback 정책에 따라 모든 `target/supportType/category`가 `기타`가 되었다.
- tags도 빈 배열이 되었다.

해결:

- Ollama 설치 확인
- `llama3.2:1b` 모델 다운로드
- `FORCE_REFINE=true`로 LLM 정제 실행
- cache에 `schemaVersion: 2` refined 결과 생성

### 문제 2. LLM 결과가 한쪽으로 쏠림

증상:

- 많은 캠페인이 `아동/청소년`, `생계지원`으로 과도하게 분류됐다.
- 예를 들어 어르신, 장애인, 동물, 해외 긴급구호 캠페인도 잘못 분류되는 사례가 있었다.

해결:

- `scripts/llm-ollama.js`에 규칙 기반 보정 로직을 추가했다.
- 명확한 키워드가 있으면 LLM 결과보다 규칙 기반 결과를 우선 적용했다.
- 예:
  - `어르신`, `노인`, `독거` → `노인`
  - `장애`, `시각장애`, `발달장애` → `장애인`
  - `유기견`, `유기묘`, `구조묘` → `동물`
  - `해외`, `미얀마`, `레바논`, `난민` → `해외/국제`
  - `식사`, `김치`, `도시락` → `식사지원`
  - `치료`, `수술`, `의료` → `의료지원`
  - `주거`, `집`, `수리` → `주거지원`
  - `폭격`, `재난`, `화재`, `긴급` → `긴급구호`

### 문제 3. tags가 단순 표시용에 머묾

기존 상태:

- tags는 카드 하단에만 표시됐다.
- 검색/분류 진입점으로 잘 쓰이지 않았다.

해결:

- 카드 상단 chip 영역에 tags를 함께 표시했다.
- tags를 `#태그` 형태로 보여주도록 변경했다.
- 태그 chip을 클릭하면 검색창에 `#태그`가 들어가고 즉시 필터링되게 했다.
- 검색창에서 `#고양이 #치료비` 같은 해시태그 검색이 가능하게 했다.

## 7. 현재 UI 반영 상태

현재 카드 상단:

```text
플랫폼 / target / supportType / #tags
```

예:

```text
Kakao Together / 노인 / 식사지원 / #식사지원 / #시각장애인 / #어르신
```

현재 필터:

- 검색어
- 대상
- 지원 유형
- 플랫폼

현재 검색:

- 일반 키워드 검색 가능
- `#태그` 검색 가능
- 태그 chip 클릭 검색 가능

검증한 예:

- `#어르신` 검색 결과: 262개
- `#식사지원` 태그 클릭 검색 결과: 113개
- `대상=노인` 필터 결과: 283개
- `대상=노인 + 지원 유형=식사지원` 필터 결과: 56개

## 8. 남은 한계

- 하나의 캠페인에 대상이 여러 개인 경우에도 현재는 `target` 하나만 선택한다.
- 하나의 캠페인에 지원 유형이 여러 개인 경우에도 현재는 `supportType` 하나만 선택한다.
- tags는 다중 키워드로 보완하지만, 완전한 다중 카테고리 구조는 아니다.
- 일부 태그는 아직 사람이 보기에 어색할 수 있어 샘플 검수가 필요하다.

## 9. 다음 추천 작업

1. 샘플 캠페인 20~30개를 직접 확인한다.
2. 어색한 tag 패턴을 추가로 제거한다.
3. 자주 쓰는 태그를 인기 태그 영역으로 따로 노출할지 검토한다.
4. 필요하면 `target/supportType`도 다중 선택 구조로 확장할지 검토한다.

## 10. 현재 결론

카테고리 문제는 기존의 단일 `category` 구조에서 벗어나 `target/supportType/tags` 구조로 정리되었다.

현재는:

- 큰 분류는 `target/supportType`
- 세부 분류와 검색 진입점은 `#tags`
- 기존 호환 필드는 `category = target`

으로 동작한다.

즉, 데이터는 검색/필터 UI에 활용 가능한 수준까지 정리되었고, 남은 작업은 샘플 품질 검수와 세부 UX 개선이다.
